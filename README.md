### 🔭 Currently: 52 weeks of AWS data engineering labs

**[preethi-somaraju/aws-labs](https://github.com/preethi-somaraju/aws-labs)** —
one lab a week for a year, from an empty AWS account to a capstone lakehouse.
Terraform for everything, free tier where possible, torn down after each lab.

Every lab records positive *and* negative tests with real command output, an
architecture diagram using official AWS icons, and a write-up including what
went wrong. A successful `terraform apply` is not treated as evidence.

| | |
|---|---|
| **Phase 1** | Identity & security — IAM, permissions boundaries, CloudTrail, KMS |
| **Phase 2** | Lake & catalog — partitioning, Parquet, Glue, Athena, Iceberg, Lake Formation |
| **Phase 3** | Batch ETL — Glue PySpark, bookmarks, EMR Serverless, dbt |
| **Phase 4** | Streaming — Kinesis, Firehose, Flink, MSK, CDC with DMS |
| **Phase 5** | Warehousing — Redshift, dist/sort keys, Spectrum, DynamoDB |
| **Phase 6** | Orchestration — Step Functions, MWAA, event-driven pipelines |
| **Phase 7** | Governance & ML — QuickSight, lineage, PII masking, SageMaker, Bedrock |
| **Phase 8** | Observability, cost, capstone |

Latest: **[Lab 01 — Account foundations](https://preethi-somaraju.github.io/blog/aws-lab-01-account-foundations.html)**
— why the budget alarm is the first resource an account should have, and what
happens when you ask S3 to make a bucket public while Block Public Access is on.
